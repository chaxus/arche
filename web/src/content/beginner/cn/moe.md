## 要点

从零若要「更大容量、可控算力」，dense FFN 会贵——**MoE** 用稀疏专家换参数量，是前沿开源（Mixtral、DeepSeek-MoE 等）主路线之一。

### 1. 有什么作用

多专家 SwiGLU + 路由：每 token **top-k** 专家，其余不算。

### 2. 从零开始：怎么生成

| 步骤 | 做什么 |
| --- | --- |
| **1** | 定专家数 E、top-k、是否共享专家 |
| **2** | 每专家一套 FFN + 路由线性 |
| **3** | 训练加负载均衡等辅助损失 |
| **4** | 推理按路由稀疏执行；检查点按专家存 |

本课是 API 引物，不是完整 Mixtral 训练栈。

### 3. 怎么样算好

| 类型 | 标准 |
| --- | --- |
| **硬** | 路由合法；top-k 合并形状对 |
| **软** | 负载不太塌；同算力下质量/容量权衡达标 |

### 4. 如何改进 · 对整模影响

| 杠杆 | 影响 |
| --- | --- |
| 更多专家 / 更大 k | 容量或算力↑ |
| 均衡损失 | 防专家塌缩 |
| 替换 dense FFN | 架构级；需按 MoE 重训 |
| 通信与落地 | 多卡专家并行是工程主成本 |

### 5. 业界 · 开源

| 系 | 做法 |
| --- | --- |
| **Mixtral** | top-2 专家 SwiGLU |
| **DeepSeek-V3** | 大规模 MoE + 精细路由 |
| **Qwen-MoE 等** | 各自 E/k 配方 |
| **Llama 3.2 1B 例子** | dense——先懂 dense 再挂 MoE |
