## 要点

从零单用户循环 → 业界要**多用户共用步进**：连续批是服务利用率的核心调度形状。

### 1. 有什么作用

多任务共享一步；结束退役；新请求填入。教学版**不是**完整 vLLM。

### 2. 从零开始：怎么生成

| 步骤 | 做什么 |
| --- | --- |
| **1** | 维护「活跃序列」集合 |
| **2** | 每步只前向仍活跃者 |
| **3** | 结束移除；接入分页 KV（后章）才接近生产 |

### 3. 怎么样算好

| 类型 | 标准 |
| --- | --- |
| **硬** | 结束必退役；序列互不串结果 |
| **软** | GPU 更满、尾延迟更稳 |

### 4. 如何改进 · 对整模影响

更好调度 → 同硬件更高吞吐。与模型权重无关，但与 KV 布局强耦合。做错会串话或漏停。

### 5. 业界 · 开源

vLLM 连续批 + paged attention 事实标准；TGI、TensorRT-LLM、SGLang 等同思路不同实现。
